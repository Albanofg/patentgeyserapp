Purpose & context
Albano is developing "Patent Geyser V1," an automated patent generation system specifically designed for software, SaaS, and blockchain utility patents. The system aims to guide inventors through creating draft provisional patent applications ready for USPTO filing or attorney review. Built as a comprehensive n8n workflow, the system consists of five sequential agents: Agent 1 (intake and initial screening), Agent 2 (refinement and specification drafting), Agent 3 (prior art search), Agent 4 (white space refinement), and Agent 5 (diagram integration). The work is serious patent development for real inventors, requiring professional-grade analysis without hallucinations.
The system is hosted on GoHighLevel (GHL) with significant administrative constraints - Albano cannot install npm packages or community nodes due to lack of admin privileges. The architecture treats the entire system as a unified n8n workflow functioning as a state machine, where each agent represents a branch with routing logic determining execution based on application state.
Current state
Albano has successfully implemented Agent 3's prior art search functionality using Google BigQuery with ML embeddings for semantic patent matching, and Agent 5's Eraser integration for generating system diagrams and flowcharts. Current focus involves debugging and refining data processing workflows, particularly JavaScript code nodes that transform AI-generated patent concept data and extract text from PDF files within the GHL environment constraints.
Recent technical challenges include resolving n8n workflow execution issues where Chat Trigger workflows don't reliably continue executing nodes after AI Agent responses, and debugging data structure mismatches between different trigger types (webhooks vs chat triggers) that require conditional handling in code nodes.
On the horizon
The primary remaining work involves completing Agent 1 (conversational intake) and Agent 2 (specification drafting with user feedback loops). Agent 1 needs to conduct conversational interviews extracting invention concepts from brief user descriptions, similar to Replit's approach of generating comprehensive concepts from initial ideas. The challenge is creating reliable handoff mechanisms between agents within the GHL hosting constraints.
Plans include implementing user authentication, multi-project management per user, and smooth transitions between agents requiring user approval at each stage. The application should feel like five distinct, specialized tools with unique UI personalities while working toward the unified goal of producing complete provisional patent drafts.
Key learnings & principles
Patent applications should focus on functional methods and system architecture rather than implementation specifics - tech stack details like programming languages and frameworks aren't necessary for patent documentation. The system requires handling highly sensitive intellectual property data that must be kept completely separate from other applications and databases.
Keyword-based triggers for agent handoffs are unreliable since users might say phrases like "perfect, but..." and accidentally trigger transitions. Button-based approval approaches work better than automated detection mechanisms. When debugging n8n workflows, targeted code changes are preferable to complete workflow replacements to avoid repeated manual configuration fixes.
Approach & patterns
Albano prefers single, focused solutions over multiple options, particularly when debugging technical issues. The development approach involves iterative debugging through conversation, identifying specific technical constraints, and adapting solutions to work within the GHL environment limitations.
For data processing, the pattern involves robust error handling, markdown cleanup for AI responses, and flexible field name detection to handle varying data structures. Workflows use conditional handling with syntax like input.chatInput || input.body.idea || input.appIdea to manage different trigger types consistently.
Tools & resources
Primary development stack includes n8n for workflow automation, GoHighLevel for hosting (with admin restrictions), Google BigQuery with ML embeddings for prior art search, OpenAI GPT models for AI processing, and Eraser API for diagram generation. For database work, Supabase is used with OAuth2 API credentials proving more reliable than Service Account credentials for Google Sheets integration.
Key technical knowledge includes n8n-specific patterns: Merge nodes require "Append" mode for parallel AI agent outputs, Chat Triggers need "Using Response Nodes" mode with proper response formatting, and Memory nodes store conversation history accessible via specific context paths. For Eraser integration, diagramType parameters must exactly match valid values like "flowchart-diagram" rather than generic terms like "flowchart."
